Déploiement & utilisation

⚠️ Dans la VM de lab uniquement

Ce sont de vrais outils offensifs. On les manipule dans la VM de formation, jamais sur un poste de prod. Le Defender du lab mettra mimikatz-master.zip en quarantaine à l'extraction : désactive la protection temps réel ou mets samples/ en exclusion avant de dézipper.

bashcd tps/purple-team/samples

# 1. Extraire mimikatz (sa source sert au test de la regle _Source)
unzip -q mimikatz-master.zip

# 2. Fabriquer le temoin negatif (un binaire quelconque, non malveillant)
cp /bin/ls _benign_control.exe

# 3. Lancer la validation complete
bash validate-yara.sh

Scanner à la main

bash# Un fichier, une regle, avec les chaines trouvees (-s)
yara -s rules/mimikatz.yar mimikatz-master/

# Tout le dossier samples/ avec toutes les regles, en recursif
yara -r rules/*.yar .

Si un sample passe en FAIL

Ça arrive si ton binaire est une version plus récente qui a renommé une chaîne. La règle n'est pas « cassée », il lui manque le bon motif. On le récupère depuis le binaire :

bash# Extraire les chaines (ascii ET utf-16 Windows), filtrer le bruit (>= 8 car.)
strings -n 8    <sample> | sort -u > a.txt
strings -n 8 -e l <sample> | sort -u > w.txt

# Reperer une chaine signante stable (nom produit, editeur, service, PDB)
grep -iE "famatech|psexesvc|gentilkiwi|sekurlsa" a.txt w.txt

# L'ajouter dans la regle correspondante, revalider :
yara -s rules/<regle>.yar <sample>

Règle d'or : un motif discriminant est spécifique à l'outil et stable (pas un numéro de version). Nom de produit, éditeur, nom de service déposé, bannière, chemin de PDB.
