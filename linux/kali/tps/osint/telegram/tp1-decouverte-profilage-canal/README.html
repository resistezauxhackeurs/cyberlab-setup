TP1 — Déploiement & prise en main

Un TP autonome pour profiler un canal Telegram public depuis l'extérieur. Bibliothèque standard Python uniquement, aucune installation de dépendance.

Prérequis Arborescence Lancer Profileur Dépannage OPSEC

Prérequis

Python3.10 ou plus (le code utilise la syntaxe str | None).
DépendancesAucune. Bibliothèque standard seule. requirements.txt est vide, c'est normal.
RéseauAccès sortant HTTPS vers t.me. Sans lui, seule la partie hors ligne tourne.
NavigateurPour les dorks et les index tiers. Idéalement deux moteurs (un Google, un non-Google).
Proxy (option)Tor + privoxy pour router le profileur si la cible est sensible.

Lancer en trois étapes

1. Vérifier l'installation (hors ligne)

terminal
$ cd tp1-decouverte-profilage-canal/code
$ python3 --version
$ python3 test_hors_ligne.py

Attendu : la liste des contrôles en [OK] et « Tous les tests passent ». Si oui, le parsing fonctionne, indépendamment du réseau.

2. Profiler le canal-graine

terminal
$ python3 profileur.py durov
$ python3 profileur.py durov --pages 3 \
    --json ../data/durov.json --md ../data/durov.md

3. Remplacer par la vraie graine de la séance

Le formateur fournit un username. On refait l'étape 2 avec, et on suit l'énoncé.

Le profileur en détail

Ce que fait profileur.py : il télécharge la page publique https://t.me/s/<canal> (celle qu'un visiteur anonyme voit), en extrait les métadonnées d'en-tête et les posts, puis reconstruit la liste des canaux liés à partir des reposts et des liens t.me cités.

Choix techniques

  • Stdlib seule (urllib, re, html.parser) : rien à installer, rien à mettre à jour, portable sur n'importe quel poste de salle.
  • Extraction par motifs sur les classes CSS stables du web preview (counter_value/counter_type, tgme_widget_message, forwarded_from_name). Un mini-parseur HTML sert de repli pour nettoyer le texte des posts.
  • Comptage dé-doublonné par post : un canal cité plusieurs fois dans le même post ne pèse qu'une fois, pour ne pas gonfler artificiellement les « liés ».
  • Pagination polie via ?before=<id> avec une pause entre pages (OPSEC + on n'agresse pas le service).

Toutes les options

OptionEffet
canalusername, @username ou URL t.me. Normalisé automatiquement.
--pages NRemonte N pages d'historique (défaut 1). Plus de pages = plus de canaux liés.
--json FICHIERÉcrit le profil complet en JSON.
--md FICHIERÉcrit une fiche lisible en Markdown.
--proxy URLRoute la requête via un proxy HTTP (ex. http://127.0.0.1:8118).
--pause SPause entre pages en secondes (défaut 1.0).

Router sous Tor (cible sensible)

terminal
$ # Tor écoute en SOCKS sur 9050 ; privoxy expose un proxy HTTP local
$ sudo apt install tor privoxy         # si absent
$ # dans /etc/privoxy/config : forward-socks5 / 127.0.0.1:9050 .
$ python3 profileur.py <canal> --proxy http://127.0.0.1:8118

Note OPSEC

◆ Ce TP est passif — et doit le rester

Tout passe par des surfaces publiques en lecture seule : moteurs, index tiers, web preview. On ne rejoint jamais le canal cible, on n'écrit rien, on ne réagit à rien. Le profileur ne fait que des requêtes GET anonymes, comme un navigateur.

Pour une cible réellement sensible : réseau dédié (VPN/Tor via --proxy), et on garde à l'esprit qu'un index tiers, lui, peut journaliser la consultation. Croiser reste plus sûr que se connecter.

⚠ Cadre d'usage

Support pédagogique de profilage OSINT défensif. Le profilage se limite à des données publiques, sur des canaux choisis dans un cadre de formation ou d'investigation légitime.
